Objective

Algorithm analysis compares algorithms by how much work they do as the input grows. In this lab you count the work of common loop shapes exactly, find the dominant term of a running-time expression, and use the two-pointer method, which needs far fewer comparisons than checking every pair.

This lab practices:

  • Counting loop body executions and condition checks exactly
  • Full, triangular, and halving loops
  • Keeping only the dominant term of a polynomial
  • Replacing an O(n2) pair search with an O(n) two-pointer search

Part 1: Exact Counts

Each method returns how many times the described operation runs for input size n. For every method in this part, a negative n causes IllegalArgumentException, and n = 0 is valid.

countLinear

public static long countLinear(int n)

Returns the number of times the body of for (int i = 0; i < n; i++) runs.

countConditionChecks

public static long countConditionChecks(int n)

Returns the number of times the condition i < n of the same loop is checked. The final check, the one that is false, counts.

countNested

public static long countNested(int n)

Returns the number of times the inner body runs when i goes from 0 to n - 1 and, for each i, j goes from 0 to n - 1.

countPairs

public static long countPairs(int n)

Returns the number of times the inner body runs when i goes from 0 to n - 1 and, for each i, j goes from i + 1 to n - 1.

countTriangle

public static long countTriangle(int n)

Returns the number of times the inner body runs when i goes from 0 to n - 1 and, for each i, j goes from 0 to i.

Part 2: Halving and Dominant Terms

countHalvings

public static int countHalvings(int n)

Returns the number of times the body of this loop runs:

int k = n;
while (k > 1) {
    k = k / 2;      // integer division
}

This equals floor(log2 n). n must be at least 1; otherwise throw IllegalArgumentException.

CallResult
countHalvings(1)0
countHalvings(5)2 (5 → 2 → 1)
countHalvings(1024)10
countHalvings(1023)9
countHalvings(0)IllegalArgumentException

dominantTerm

public static String dominantTerm(long c0, long c1, long c2, long c3)

The running time of an algorithm is c0 + c1*n + c2*n2 + c3*n3. Return its Big-O class as one of exactly these four strings: "O(1)", "O(n)", "O(n^2)", "O(n^3)".

  • The class is decided by the highest power of n whose coefficient is not zero. The size of the coefficient does not matter, and a negative coefficient still counts as non-zero.
  • If c1, c2, and c3 are all zero, the class is "O(1)", even when c0 is also zero.

dominantTerm(0, 0, 1000000, 1)"O(n^3)"
dominantTerm(0, 0, 0, 0)"O(1)"

Part 3: Counting Pairs With a Given Sum

Both methods take an array sorted that is in strictly increasing order (no duplicates). If sorted is null, or any element is not larger than the one before it, throw IllegalArgumentException. An empty array and a one-element array are valid.

Use the two-pointer method: left starts at index 0 and right at the last index. While left < right, compute sum = sorted[left] + sorted[right] (one comparison), then:

  • sum == target: a pair is found; move both pointers inward (left++, right--).
  • sum < target: left++.
  • sum > target: right--.

Compute the sum in long so that large values cannot overflow.

countPairsWithSum

public static int countPairsWithSum(int[] sorted, int target)

Returns the number of pairs of positions i < j with sorted[i] + sorted[j] == target. The array is not changed.

twoPointerComparisons

public static int twoPointerComparisons(int[] sorted, int target)

Returns how many sums the two-pointer method above computes before left and right meet. For an array of length n, this is at most n - 1 (and 0 when n is 0 or 1). The array is not changed.

countPairsWithSum(a, 7)3 (1+6, 2+5, 3+4)

Example

For a = [1, 2, 3, 4, 5, 6] and target = 3, the pointers move like this:

leftrightsumAction
057too large, right--
046too large, right--
035too large, right--
024too large, right--
013pair found, both move

Then left = 1 and right = 0, so the search stops after 5 comparisons with 1 pair.

Required Edge Cases

Your implementation must correctly handle:

  • n = 0 and n = 1 in every method of Parts 1 and 2 where they are valid
  • Negative n, and countHalvings(0)
  • Very large n (for example 2000000000) without int overflow and without running a loop
  • null, unsorted, and duplicate-containing arrays in Part 3
  • Empty and one-element arrays, and targets with no pair
  • Negative numbers and values near Integer.MAX_VALUE in the arrays
