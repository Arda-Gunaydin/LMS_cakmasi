Objective

An undirected graph is stored as an adjacency list: every vertex is a Node<T> that keeps the list of its neighbors, and the Graph<T> finds the node of a value through a Map<T, Node<T>>. You implement building and changing the graph, the two graph traversals, and the shortest path in an unweighted graph.

This lab practices:

  • Keeping an undirected edge consistent: it is stored in both neighbor lists
  • Breadth-first search with a queue and a visited set
  • Recursive depth-first search
  • Shortest paths with BFS and parent pointers, then rebuilding the path backwards

Part 1: Node<T>

MethodReturn typeRequired behavior
addNeighbor(Node<T> neighbor)voidAppends neighbor to neighbors. Nothing happens if it is null, the node itself, or already a neighbor.
removeNeighbor(Node<T> neighbor)voidRemoves neighbor from neighbors if it is there.

Part 2: Building the Graph

MethodReturn typeRequired behavior
addNode(T data)voidAdds a new node with no neighbors, unless data is null or already has a node (then nothing changes and the existing edges are kept).
addEdge(T data1, T data2)voidCreates the missing nodes, then adds each node to the other's neighbor list. Nothing happens if either value is null or both are equal (no self-loops). An existing edge is not added twice.
removeEdge(T data1, T data2)voidIf both nodes exist, removes the edge in both directions. The nodes stay in the graph.
removeNode(T data)voidIf the node exists, removes it from every neighbor list and then from nodes. Otherwise nothing happens.

Part 3: Traversals and Shortest Path

All three methods return a new list of values. If the start value has no node, they return an empty list.

MethodReturn typeRequired behavior
bfs(T startData)List<T>Breadth-first order from the start: use a queue; mark a node visited when it is added to the queue; add each dequeued node to the result, then enqueue its unvisited neighbors in list order. Only the start's connected component is visited.
dfs(T startData)List<T>Recursive depth-first order (use dfsHelper): add the current node, then recursively visit each unvisited neighbor in list order.
getShortestPath(T startData, T endData)List<T>A path with the fewest edges, from startData to endData, both included. Run BFS from the start, setting each newly discovered node's parent (neighbors in list order, so among equally short paths the one BFS finds first is returned), then follow parent back from the end and reverse. The same value twice gives a one-element path. If either node is missing or the end cannot be reached, return an empty list. The visited/parent fields must be reset at the start of every call, so the method works when called many times.

Example

Graph<String> g = new Graph<>();
g.addEdge("A", "B");
g.addEdge("A", "C");
g.addEdge("B", "D");
g.addEdge("C", "D");
g.addEdge("D", "E");

        A
       / \
      B   C          neighbors of A: [B, C]
       \ /           neighbors of D: [B, C, E]
        D
        |
        E

g.bfs("A")                  // [A, B, C, D, E]
g.dfs("A")                  // [A, B, D, C, E]
g.getShortestPath("A", "E") // [A, B, D, E]
g.getShortestPath("E", "A") // [E, D, B, A]
g.getShortestPath("A", "A") // [A]
g.bfs("Z")                  // []

g.removeNode("D");
g.bfs("A")                  // [A, B, C]
g.getShortestPath("A", "E") // []   (E is no longer reachable)

Required Edge Cases

Your implementation must correctly handle:

  • Duplicate nodes and edges, self-loops and null values (ignored)
  • Removing a missing edge or node, and removing a node that has many edges
  • Cycles: no node may appear twice in a traversal
  • Disconnected graphs: traversals only visit the start's component; unreachable targets give an empty path
  • A start or end value that is not in the graph
  • Calling getShortestPath several times on the same graph

Suggested Order

  1. addNeighbor, removeNeighbor
  2. addNode, addEdge, removeEdge, removeNode; use printGraph to look at the result
  3. bfs, then dfs with dfsHelper
  4. getShortestPath
