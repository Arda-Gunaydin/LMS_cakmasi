CSE201 Data Structures
Lab 5: Queues

Objective

A queue is a first-in-first-out (FIFO) collection: items are added at the back (enqueue) and removed from the front (dequeue), so the item that has waited longest leaves first. In this lab you build two queues from scratch, a circular array queue and a linked queue, and then use them to solve two classic queue problems: the hot potato elimination game and generating binary numbers.

This lab practices:

  • Implementing a generic queue on a circular array with a moving front index
  • Growing a circular array without breaking the order of its items
  • Keeping both a head and a tail reference correct in a linked queue
  • Solving a problem by moving items between the front and the back of a queue
The 2 static methods you have to write
public static String hotPotato(String[] players, int k)
public static String[] generateBinary(int n)

Part 1: CircularQueue<T>

Create class CircularQueue<T>. It stores its items in a private array that is used as a circle: when the end of the array is reached, the next item goes to index 0 if that slot is free. No item is ever shifted to the left. The queue only remembers where the front is.

Fields

FieldTypeRequirements
itemsT[]The internal array. Its length is the capacity. Create it with (T[]) new Object[capacity]. Slots that hold no item must be null.
frontintThe index in items of the item at the front of the queue. Starts at 0.
sizeintThe number of items in the queue.

Constructors

  • CircularQueue(int initialCapacity): the internal array starts with this length. initialCapacity must be at least 1, otherwise IllegalArgumentException.
  • CircularQueue(): the same as CircularQueue(8).

Methods

MethodReturn typeRequired behavior
enqueue(T item)voidAdds item at the back. The back slot is (front + size) % items.length. null causes IllegalArgumentException. When the array is full, first replaces it with an array of twice the length that holds the same items in the same order, starting at index 0, and sets front to 0.
dequeue()TRemoves and returns the front item. Sets the freed slot back to null and moves front one step forward, wrapping to 0 at the end of the array. On an empty queue, throws java.util.NoSuchElementException. Does not shrink the array.
peek()TReturns the front item without removing it. On an empty queue, throws java.util.NoSuchElementException.
isEmpty()booleantrue when the queue has no items.
size()intNumber of items currently in the queue.
capacity()intCurrent length of the internal array.
toString()StringThe items from front to back, for example after enqueue(10), enqueue(20), enqueue(30): [10, 20, 30] (the first element shown is the front). An empty queue gives [].

Example

CircularQueue<Integer> q = new CircularQueue<>(4);
q.enqueue(1); q.enqueue(2); q.enqueue(3); q.enqueue(4);
// items = [1, 2, 3, 4]        front = 0   size = 4   capacity 4
q.dequeue();                   // returns 1
q.dequeue();                   // returns 2
// items = [null, null, 3, 4]  front = 2   size = 2
q.enqueue(5);
q.enqueue(6);
// items = [5, 6, 3, 4]        front = 2   size = 4   (5 and 6 wrapped around)
// toString() is [3, 4, 5, 6]  and capacity() is still 4
q.enqueue(7);                  // full: the array grows to 8 and is copied in queue order
// items = [3, 4, 5, 6, 7, null, null, null]   front = 0   size = 5   capacity 8

Part 2: LinkedQueue<T>

Create class LinkedQueue<T>. It is built from singly linked nodes, uses no array, and has no capacity: it grows by one node per item. The starter already contains the private inner class Node.

Constructor

Part 3: Queue Applications

Both methods are static methods of Lab05. Each one must use one of your own queues (CircularQueue or LinkedQueue) to do its work.

hotPotato

public static String hotPotato(String[] players, int k)

The players stand in a queue in the order of the array, the first player at the front. Each round the potato is passed k times: the first k - 1 players at the front each move, one at a time, to the back of the queue, and the k-th player is eliminated. Rounds are repeated until one player is left. Return the name of that last player.

  • players is never modified.
  • A single player wins immediately, whatever k is.
  • k may be larger than the number of players.
  • null, an empty array, a null element, or k < 1 causes IllegalArgumentException.
CallResult
hotPotato(["A", "B", "C", "D"], 3)"A"
hotPotato(["A", "B", "C"], 1)"C"
hotPotato(["Solo"], 4)"Solo"
hotPotato(["A", "B"], 0)IllegalArgumentException

generateBinary

public static String[] generateBinary(int n)

Returns a new array of length n whose element at index i is the binary representation of i + 1, without leading zeros. Do not use Integer.toBinaryString or any conversion method. Generate the values with a queue: start with "1" in the queue; to produce each value, dequeue a string s, store it, then enqueue s + "0" and s + "1". n < 1 causes IllegalArgumentException.

CallResult
generateBinary(1)["1"]
generateBinary(5)["1", "10", "11", "100", "101"]
generateBinary(0)IllegalArgumentException

Required Edge Cases

Your implementation must correctly handle:

  • dequeue() and peek() on an empty queue, in both classes
  • A CircularQueue whose items wrap around the end of the array, both for toString() and for dequeue()
  • Growing a CircularQueue while its items are wrapped, and a CircularQueue(1) that grows several times
  • A LinkedQueue that becomes empty and is then used again (tail must not point to a removed node)
  • hotPotato with k = 1, one player, and k larger than the number of players
  • Invalid arguments: null items, capacity below 1, k < 1, n < 1

Suggested Order

  1. Write LinkedQueue first: it has the fewest details. Test it with the playground in main.
  2. Write CircularQueue without growing: constructor, enqueue into a non-full queue, dequeue, peek, toString.
  3. Make enqueue and toString use the wrap-around index (front + i) % items.length.
  4. Add growing, and check it with a queue whose front is not at index 0.
  5. Write generateBinary, then hotPotato.
