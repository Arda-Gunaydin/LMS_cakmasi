Objective

In this lab you do not write algorithms: you analyze them. For each of seven given methods you decide its running time as a Big-O bound in terms of n, the length of the array a. Then you answer five questions that compare an array with a singly linked list.

This lab practices:

  • Counting how many times the innermost statement of nested loops runs
  • Recognizing logarithmic loops (a variable that is halved or doubled each step)
  • Recognizing exponential recursion (two recursive calls on a problem only one smaller)
  • Comparing the cost of basic operations on arrays and linked lists

Part 2: Array vs. Singly Linked List

Each method question1() to question5() has two answers: arrayAnswer and sllAnswer. Allowed answers are "1", "n" and "n+m". Assume:

  • The array has a size counter and enough spare capacity, so it never has to grow. Its elements must stay in positions 0 to size - 1 with no gaps.
  • The singly linked list has only a head reference, except in Q5, where it also has a tail reference.
  • In Q5 the two structures have n and m elements, and the result must be one structure that holds both.
MethodQuestion
question1()Accessing an element by index.
question2()Searching for an element in an unsorted structure.
question3()Inserting an element at the end.
question4()Deleting the first element.
question5()Concatenating two structures (the SLL has a tail pointer).

A question earns its check only when both answers are correct.

Required Edge Cases

Think about:

  • Loops whose bound depends on the outer loop variable (a triangle still grows like a square)
  • Constant work that does not depend on n at all
  • A loop that runs log n times around a loop that runs n times
  • Why removing the first element is expensive in an array but cheap in a linked list, and the reverse for access by index
