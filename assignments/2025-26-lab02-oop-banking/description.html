Objective

You model a small bank: customers own accounts, accounts keep a sorted history of transactions, and customers pay with a payment method. The lab reviews the object-oriented tools you need for the rest of the course.

This lab practices:

  • An interface (PaymentMethod) with two implementations
  • Abstract classes (Account, Customer) with abstract methods that the subclasses override
  • Encapsulation: private helper methods and private/protected fields
  • Comparable and a sorted collection (TreeSet)

The Grading Contract

In this lab some methods print messages, and the tests compare that printed text exactly. The other methods are graded by their return values and by the object's state.

Because of that:

  • Method names, parameter types, parameter order, and return types must match this document exactly.
  • Printed messages must match the formats below character by character. Write amounts with %.2f in System.out.printf (or String.format), exactly as shown.
  • Methods that are not said to print must not print anything.
  • A file that does not compile earns no points, so save and evaluate early rather than in the last minute.

General Rules

CheckingAccount extends Account

Constructor CheckingAccount(String accountNumber, double initialBalance, double overdraftLimit).

  • withdraw(amount): amount ≤ 0 throws IllegalArgumentException.
  • If amount ≤ balance + overdraftLimit: the balance goes down (it may become negative), a "WITHDRAWAL" transaction is recorded, it prints Withdrew %.2f from <accountNumber>. New balance: %.2f and returns true.
  • Otherwise nothing changes, it prints Withdrawal %.2f denied for <accountNumber>. Exceeds overdraft. and returns false.

SavingsAccount extends Account

Constructor SavingsAccount(String accountNumber, double initialBalance, double interestRate) (0.05 means 5%).

  • withdraw(amount): like CheckingAccount, but the limit is the balance itself (no overdraft), and the refusal message is Withdrawal %.2f denied for <accountNumber>. Insufficient funds.
  • applyInterest() (void): computes interest = balance * interestRate, adds it with deposit(interest) (so it is recorded as a "DEPOSIT", and an interest of 0 throws IllegalArgumentException), then prints Applied interest %.2f to <accountNumber>. New balance: %.2f.

Example

Bank bank = new Bank();
Customer ali = new RegularCustomer("C1", "Ali");
bank.addCustomer(ali);
bank.openAccountForCustomer("C1", new CheckingAccount("CHK-1", 100.0, 50.0));   // true
bank.openAccountForCustomer("C9", new SavingsAccount("SAV-9", 0.0, 0.01));      // false (no C9)

Account chk = bank.findAccount("CHK-1");
chk.withdraw(130.0);   // true   prints: Withdrew 130.00 from CHK-1. New balance: -30.00
chk.withdraw(30.0);    // false  prints: Withdrawal 30.00 denied for CHK-1. Exceeds overdraft.
chk.toString();        // "CHK-1 | Balance: -30.00"

SavingsAccount sav = new SavingsAccount("SAV-1", 800.0, 0.05);
sav.applyInterest();   // prints: Applied interest 40.00 to SAV-1. New balance: 840.00

ali.setPaymentMethod(new CreditCardPayment("1234 5678 9012 3456", "Ali Veli"));
ali.makePayment(50.0);
// prints: Ali (fee 2.50) making payment: Paid 50.00 with credit card ****-****-****-3456 (holder: Ali Veli)
ali.setPaymentMethod(new PayPalPayment(""));
ali.makePayment(10.0);
// prints: Ali (fee 2.50) making payment: Cannot connect.

The tests build the expected text with the same %.2f formatting, so the decimal separator is whatever Java uses on the computer that runs them.

Required Edge Cases

Your implementation must correctly handle:

  • Card payments of 0, exactly 10000.0, just above it, and negative amounts; a null or blank holder name
  • Card numbers with spaces, and with 4 or fewer digits
  • A null or blank PayPal email
  • Withdrawing exactly the balance (savings) and exactly balance + overdraft (checking); 0 and negative amounts
  • deposit of 0 or a negative amount
  • makePayment without a payment method
  • findCustomer / findAccount for ids that do not exist
