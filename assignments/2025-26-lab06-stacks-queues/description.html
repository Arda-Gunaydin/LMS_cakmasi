Objective

A stack is last-in, first-out (LIFO): push adds on top and pop removes from the top. A queue is first-in, first-out (FIFO): enqueue adds at the rear and dequeue removes from the front. In this lab you implement each of them twice: once on a fixed-size array and once on linked nodes.

This lab practices:

  • An array-based stack that uses one index (top) to know where the next item goes
  • A circular array-based queue (front and size, indexes wrap around with %)
  • A linked stack (insert and remove at the head) and a linked queue (insert at rear, remove at front)
  • Programming to an interface: all four classes can be used as a Stack<E> or a Queue<E>

Part 1: ArrayStack<E>

Fields

FieldTypeRequirements
dataE[]The items. data[0] is the bottom of the stack. Length is always 4.
topintThe index where the next pushed item goes, which is also the number of items.

Rules

  • push writes to data[top] and increases top. A fifth push onto a full stack is ignored.
  • pop must set the freed slot back to null so the array does not keep a reference to a removed item.

Part 2: ArrayQueue<E> (circular)

Fields

FieldTypeRequirements
dataE[]The items. Length is always 4.
frontintIndex of the front item.
sizeintNumber of items.

Rules

  • The rear slot is (front + size) % data.length; enqueue writes there.
  • dequeue sets the old front slot to null and moves front to (front + 1) % data.length. Items are never shifted.
  • Because the indexes wrap around, after dequeue frees a slot the queue can hold 4 items again. It is full only when size == 4.

Part 3: LinkedStack<E>

Uses the given Node<E> (data, next). The field top is the node of the top item (null when empty); each node's next points to the item below it. push and pop work at top in O(1). There is no capacity limit.

Part 4: LinkedQueue<E>

front is the node of the front item and rear the node of the last item. enqueue links a new node after rear; dequeue removes the front node. Both are O(1). When the last item is dequeued, both front and rear must become null, so that a later enqueue works. There is no capacity limit.

Example

ArrayQueue<Integer> q = new ArrayQueue<>();
q.enqueue(1); q.enqueue(2); q.enqueue(3); q.enqueue(4);   // full: [1, 2, 3, 4], front = 0
q.enqueue(5);            // ignored, still 4 items
q.dequeue();             // 1   -> data = [null, 2, 3, 4], front = 1
q.dequeue();             // 2   -> data = [null, null, 3, 4], front = 2
q.enqueue(5);            //     -> data = [5, null, 3, 4]   (wrapped around to index 0)
q.enqueue(6);            //     -> data = [5, 6, 3, 4], size = 4
q.dequeue();             // 3
q.front();               // 4

Stack<String> s = new LinkedStack<>();
s.pop();                 // null (empty)
s.push("a"); s.push("b");
s.top();                 // "b"
s.pop();                 // "b"
s.size();                // 1

Required Edge Cases

Your implementation must correctly handle:

  • pop, top, dequeue and front on an empty structure (return null)
  • push / enqueue on a full array structure and with a null item (ignored)
  • An array queue whose items wrap around the end of the array, many times in a row
  • Emptying a structure completely and then using it again
  • Many items (for example 100) in the linked versions

Suggested Order

  1. ArrayStack, then LinkedStack
  2. LinkedQueue
  3. ArrayQueue (the circular one is the trickiest)
