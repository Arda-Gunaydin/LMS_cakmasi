Objective

A binary min-heap is a complete binary tree in which every parent is ≤ its children, so the minimum is always at the root. You implement the interface Heap<E extends Comparable<E>> twice, then use the heap idea to sort an array in place.

  • ArrayHeap: the tree is stored in an array. The children of index i are 2i + 1 and 2i + 2, and the parent is (i - 1) / 2.
  • LinkedHeap: the same tree built from nodes with left, right and parent references. It needs a breadth-first search to find the next free or the last position, which shows why heaps are almost always implemented with arrays.
  • Lab09.heapSort: an in-place heap sort that uses a max-heap.

The Heap<E> Interface

removeMin()ERemoves and returns the root: the last element replaces the root, the last position is deleted, then heap-down from the root. null when empty.

Heap-up and heap-down rules (both classes)

  • Heap-up: while the element has a parent and the parent is strictly greater (parent.compareTo(child) > 0), swap them and continue from the parent.
  • Heap-down: while the element has a left child: pick the smaller child (if both children are equal, pick the left one); if the element is ≤ that child, stop; otherwise swap and continue from the child.

Part 1: ArrayHeap<E>

  • Elements are in data[0] to data[size - 1]; every other slot is null (removeMin must clear the old last slot).
  • insert: 1) put the element at data[size], 2) heapUp(size), 3) size++. If the array is full, first replace it with a copy of twice the length, so a heap can hold any number of elements.
  • swap(i, j) swaps two array slots.

merge

public static <E extends Comparable<E>> ArrayHeap<E> merge(ArrayHeap<E> h1, ArrayHeap<E> h2)

Returns a new heap with all elements of both heaps, built in O(n) with the bottom-up build-heap algorithm:

  1. Create a new ArrayHeap whose array has length max(64, n1 + n2).
  2. Copy h1's elements (in their array order), then h2's elements right after them.
  3. Call heapDown(i) for i = size / 2 - 1 down to 0.

h1 and h2 must not change. A null argument counts as an empty heap.

Part 2: LinkedHeap<E>

  • insert: on an empty heap the new node is the root. Otherwise a breadth-first search (queue) from the root finds the first node with a missing left (checked first) or right child. Attach the new node there, set its parent, then heap-up by swapping values (not nodes) with the parent.
  • removeMin: 1) find the last node with a breadth-first search, 2) save the root value, 3) copy the last node's value into the root, 4) detach the last node from its parent, 5) heap-down from the root by swapping values, 6) return the saved value. Removing the only node makes root null.
  • The values of a LinkedHeap in level order are always exactly the array of an ArrayHeap that got the same operations.

Part 3: heapSort

public static <E extends Comparable<E>> void heapSort(E[] arr)

Sorts arr in ascending order, in place, without a second array:

  1. Build a max-heap in the array: call heapifyUp(arr, arr.length, i) for i = arr.length / 2 - 1 down to 0.
  2. For end = arr.length - 1 down to 1: swap arr[0] (the maximum) with arr[end], then heapifyUp(arr, end, 0).

The private helper heapifyUp(arr, heapSize, i) (last year's name; it actually moves the element down) makes the subtree at i a max-heap: find the largest of arr[i] and its children inside heapSize; if it is a child, swap and continue from that child. A null array or an array with fewer than 2 elements is left as it is.

Example

ArrayHeap: insert 5, 3, 8, 1
  [5]  ->  [3, 5]  ->  [3, 5, 8]  ->  [1, 3, 8, 5]
insert 4        ->  [1, 3, 8, 5, 4]
removeMin() = 1 ->  4 moves to the root and goes down: [3, 4, 8, 5]

merge([1, 5, 9], [2, 4]):
  copy       [1, 5, 9, 2, 4]
  heapDown(1): 5 > smaller child 2 -> [1, 2, 9, 5, 4]
  heapDown(0): 1 ≤ 2, stop     -> result [1, 2, 9, 5, 4]

LinkedHeap with the same inserts 5, 3, 8, 1:

        1
       / \
      3   8
     /
    5

heapSort([9, 4, 7, 1, 8])  ->  [1, 4, 7, 8, 9]

Required Edge Cases

Your implementation must correctly handle:

  • min and removeMin on an empty heap and on a one-element heap
  • Duplicates, and equal children during heap-down (take the left one)
  • More than 64 inserts into an ArrayHeap
  • merge with an empty or null heap; the inputs stay unchanged
  • LinkedHeap: correct parent references, and removing the right or the left child as the last node
  • heapSort on null, an empty array, one element, duplicates, already sorted and reverse-sorted arrays

Suggested Order

  1. ArrayHeap: swap, heapUp, insert, min, heapDown, removeMin, then merge
  2. LinkedHeap
  3. heapifyUp and heapSort
